# 模式选择器蒸馏 MPC：实验观察与 RL 抽象层次

## 1. 背景：这个 MPC 不是"优化式 MPC"

`RollingNativeMpcController` 并不求解任何优化问题。它每 24 h 重规划一次，做法是：

1. 准备一个**候选启发式库**：`greedy`、`forecast_urgency`、以及每一种"船→源"专属分配（dedicated assignment，3 船 3 源 = 6 种排列）；
2. 对每个候选，**在环境副本里用真实仿真器 + 扰动预报 rollout 168 h**；
3. 按字典序 `(放空 → 期末未处理库存 → 运营成本)` 挑最好的候选；
4. 执行该候选未来 24 h 的动作，然后重新选（可切换）。

**结论：MPC 的"策略"本质是一个低维、预报条件的"模式选择"——每 24 h 从 ~8 个可解释模式里选一个。它的智能全在"选哪个模式"，而不是逐步动作。**

## 2. 蒸馏思路：学"选择"，不学"逐步动作"

对逐步原生动作做 BC/PPO 会在 720 h 内产生 covariate shift（见 forecast BC/PPO 报告：PPO-state 放空 14,516 t，反而**劣于** greedy 的 8,019 t）。

改为蒸馏**模式选择**：在每次 replan 采集 `(当前 state + forecast 摘要 → MPC 选中的模式)`，训练一个分类器；部署时每 24 h 用分类器选模式，再跑该模式的确定性启发式（自洽、不漂移）。

## 3. 实验设置

| 项目 | 设置 |
|---|---|
| 场景 | `northern_lights_phase1_3vessels`（3 船 3 源 1 井） |
| 扰动 | block 天气 [0.75,1.0]、capture_noise 0.10、high-output 事件 0.5/周·48h·[1.25,1.75]、无 outage/maintenance |
| reward_mode | `vent_first` |
| 特征 | 51 维 state + forecast 全局 mean/min/max 摘要（96 维） |
| 分类器 | RandomForest（300 树） |
| 训练/评估 | 20 训练 seed（~600 标签，8 类）/ 10 held-out seed |

## 4. 结果（10 个 held-out seed）

| 控制器 | 放空 t | Storage | 每吨成本 |
|---|---:|---:|---:|
| greedy | 7,689 | 81.7% | 19.9 |
| **MPC（oracle）** | **874** | **86.2%** | **15.2** |
| mode_selector（蒸馏） | 6,182 | 81.7% | 19.4 |

> 注：2-seed smoke 曾得到 2,834 t，是小样本噪声，不可信；以 10-seed 为准。

## 5. 关键发现

1. **方向验证成功**：mode_selector（6,182 t）**超过 greedy**（7,689 t，放空少 ~20%），成本略低。**这与蒸馏逐步动作的 BC/PPO（14,516 t，劣于 greedy）形成鲜明对比——"蒸馏模式选择 ≫ 蒸馏逐步动作"。**
2. **但离 MPC 仍差很远**（6,182 vs 874）。瓶颈在**分类器的模式预测**，不在方法。
3. **瓶颈成因**：
   - forecast 特征太粗（全局 mean/min/max），**丢掉了"哪个源、什么时候高产"的时序信息**——而 MPC 恰恰靠精确 rollout 区分该选哪个 dedicated 排列；
   - RandomForest `train_acc=1.0` 过拟合，held-out 上会选错模式；
   - MPC 用**精确 rollout** 选模式，分类器只看**汇总快照**，信息本就不对等。

## 6. 如何解释分类器结果（避免误导）

**准确率是错的指标**：两个模式可能给出几乎相同的结果（平局），且 MPC 在平局时的 argmax 是任意的——这解释了 `train_acc=1.0` 但 held-out 差。应改看：

- **Regret（后悔值）**：对每次 replan，把分类器选的和 MPC 选的都 rollout 比目标差；regret≈0 的错分类是无害的，regret 大的才是真错。
- **混淆矩阵**：看谁和谁混、混得有没有害（结合 regret）。
- **特征重要性 / SHAP**：因为模式和特征都可解释，可读出学到的规则，预期是"**把船调度向即将高产的源**"——物理上合理。
- **物理对照**：抽样检查"forecast 显示某源要 surge 时，是否真的选了 dedicate-to-该源"。

## 7. 核心洞察：RL 的正确抽象层次是"高层选择"，不是"底层控制"

经典直觉是"RL = 底层控制"（机器人连续控制），但**在本问题里这个关系是反的**：

| | 机器人（直觉来源） | 本问题（CCS 物流） |
|---|---|---|
| 底层 | 连续、动态复杂 → RL 有用 | 离散、启发式已近最优 → RL **没头空间** |
| 高层 | 规则/规划够用 | 组合选择 + 前瞻价值大 → RL **有用** |

证据：
- **底层近最优**：给定模式，确定性 cluster/greedy 执行已近最优；residual RL、部分卸货都只能追平（"超不多"）。
- **头空间在选择**：MPC 打败 greedy 靠"选对模式"，不靠"执行更好"。
- **底层 RL 正是失败的那个**：报告里逐步动作 PPO 崩掉（covariate shift）。

**因此正确分层：**

```
高层：模式/目标选择（8 类 / 24h）   ← RL 放这里
        BC warm-start（蒸馏 MPC）→ PPO on 真 reward
        空间小、可训、有头空间、可能超过 MPC
低层：模式对应的确定性启发式        ← 不用 RL（已近最优）
```

**当前蒸馏是监督模仿（不是 RL），封顶在 MPC。要超过 MPC，需在"模式选择"这一层做 BC→PPO（真 reward）——这是一个极小的离散 RL 问题（8 类/24h、~30 决策/episode），既可训、又可能超过 MPC 的短视 rollout 选择。**

## 8. 下一步

| 优先级 | 动作 | 目的 |
|---|---|---|
| P0 | 诊断：held-out **regret + 混淆矩阵 + 特征重要性** | 定位瓶颈、可解释 |
| P1 | **per-emitter × per-window** 细化 forecast 特征；换正则化 GBDT / 加训练 seed | 拉近 MPC |

| P2 | **混合：分类器 top-K + 短窗口 rollout** | 保留 MPC 判别力、仍快 |

## 9. 诚实的元判断

| 目标 | 需要 RL 吗 |
|---|---|
| 匹配 MPC（快速部署、抗漂移） | 不需要，监督蒸馏即可 |
| **超过 MPC** | 需要，在模式层做 BC→PPO on 真 reward |
| 学更好的模式/技能、泛化/鲁棒 | 需要 RL（和 LLM） |

**一句话：这次实验证明"蒸馏 MPC 的模式选择"是正确抽象——它超过了 greedy、且比蒸馏逐步动作稳健得多；但当前分类器太弱，离 MPC 仍有差距。真正的 RL 落点是"高层模式选择"，用它去超过 MPC，而不是底层逐步控制。**
