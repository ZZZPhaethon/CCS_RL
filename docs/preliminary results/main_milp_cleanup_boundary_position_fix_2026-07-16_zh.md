# 主 MILP cleanup 边界船位修复与求解难度复核

日期：2026-07-16

## 修复内容

主 MILP 会把尚未在 168 h 边界前抵达的航行弧截断到规划边界。旧的 cleanup 接口直接把这种弧视为已经抵达目的地，因此遗漏了边界后的剩余航程。

现在每条跨边界航行弧都携带一个由边界剩余距离计算得到的名义燃油小时数：

\[
C_{\mathrm{residual\ sail}}
=\sum_a x_a h_a^{\mathrm{remaining}}c_{\mathrm{fuel/h}}.
\]

船舶仍然先到达该弧的目的地，再进入原纯航次 cleanup 的协调分配。修复没有增加新的变量、整数变量或约束，只增加线性目标系数；`terminal_cleanup_value=False` 时完全不启用。

## 是否使 MILP 更难求解

没有观察到结构性变难：

- 修复前后每个窗口的 presolve 行数和列数完全相同；
- 没有增加任何 branch-and-bound 整数决策；
- 修复后墙钟时间仍为 32.6–33.2 s，与30 s限时下原结果相同；
- 4个窗口均找到整数可行解，没有出现无 incumbent 或 warm start 被拒绝。

目标系数改变后，30 s gap 比修复前高约2–3.5个百分点：

| 状态时刻 | 修复前gap | 修复后gap |
|---:|---:|---:|
| 0 | 32.64% | 34.62% |
| 168 | 27.63% | 30.59% |
| 384 | 28.50% | 31.48% |
| 552 | 35.50% | 36.53% |

这表示固定30 s内的bound/incumbent搜索略有波动，不表示cleanup子模型规模变大。所有结果仍为 `Integer Feasible`，没有任何窗口证明Optimal。
