# `Simulation.operations`

本目录实现单个时间步中的领域物理操作。它们由 `PhysicalNetwork` 调用，读取
已解析动作和 `PhysicalState`，更新库存/流量，并将不可满足的请求写入
`Violation`。

| 文件 | 物理职责 |
| --- | --- |
| `capture.py` | 计算捕集量、排放源缓冲库存和因缓冲不足造成的放空。 |
| `loading.py` | 按船舶容量、装载速率和靠泊状态从 emitter 装载 CO₂。 |
| `transport.py` | 投影管道流量，并将管道输出分配给可用注入井。 |
| `unloading.py` | 维护终端卸载队列，按泊位和卸载能力卸载船舶。 |
| `injection.py` | 计算井/储层能力，并将 CO₂ 注入储层。 |
| `pressure_limits.py` | 使用储层压力和线源井底压力限制允许的注入速率。 |
| `snapshot.py` | 生成包含库存、能力、压力和扰动信息的诊断快照。 |
| `validation.py` | 在每个网络时间步后审计库存、容量、流量、压力和质量守恒不变量。 |

所有操作应遵循三个原则：不产生负库存、不超过设备/压力能力、保持质量守恒。
违反请求不应被静默忽略，而应在 `StepResult.violations` 中留下可审计记录。

对于 RL，操作模块定义了动作的真实可行域。环境应根据**实际执行的流量**而不是
仅根据策略请求量计算奖励和下一状态。
