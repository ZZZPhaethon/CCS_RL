# `Simulation.entities`

本目录定义 CCS（碳捕集与封存）仿真中的静态物理实体、动态状态和
时间步结果。实体类大多使用 `@dataclass(frozen=True)`：它们描述场景的
固定能力和物理参数；随时间变化的库存、流量、队列和扰动则保存在
`PhysicalState` 中。

对强化学习（RL）而言，这种分离很重要：实体定义了动作的可行域和系统
瓶颈，`PhysicalState` 是构建观察（observation）的主要来源，`StepResult`
和 `Violation` 则可用于奖励、约束成本和调试。

## 文件与职责

| 文件 | 主要内容 | 在系统中的作用 | 对 RL 的潜在影响 |
| --- | --- | --- | --- |
| `emitter.py` | `Emitter` | 描述排放源的捕集能力、缓冲容量、可用率及逐小时捕集曲线。 | 决定 CO₂ 供给、放空风险和捕集调度空间；可用率与捕集曲线应进入观察或扰动输入。 |
| `pipeline.py` | `Pipeline`、`Coordinate` | 描述管道的瞬时/年度输送能力和路径元数据。 | `max_flow_tph` 与年度容量形成硬约束；管道拥塞会改变最优的船运和注入分配。 |
| `terminal.py` | `Terminal` | 描述中转终端的库存容量和可同时靠泊的船舶数。 | 库存、泊位数和卸载队列会产生拥塞与等待，应影响船舶调度动作和延迟惩罚。 |
| `vessel.py` | `Vessel` | 描述船舶的载量、装卸速率、体积容量和航速。 | 决定批量运输能力、航次时间和终端排队；船舶指派/航线选择通常是离散动作。 |
| `manifold.py` | `SubseaManifold` | 描述海底歧管的最大通过流量。 | 是注入端共享瓶颈；多井分配不能超过该流量上限。 |
| `storage.py` | `InjectionWell`、`Reservoir` | 描述注入井能力、储层容量、压力限制和线源模型关联参数。 | 直接限定注入动作；压力裕度和剩余容量应作为长期规划观察，以避免短视注入。 |
| `line_source.py` | `LineSourceParameters` 与压力计算函数 | 基于线源模型计算恒定/变注入速率、多井干扰和井底压力。 | 将注入决策转化为随时间累积的压力约束；多井干扰使动作耦合且具有长期后果。 |
| `state.py` | `PhysicalState`、`Violation`、`StepResult` | 保存动态状态、约束违规和单步仿真结果。 | `PhysicalState` 可构成观察；`Violation` 和质量平衡误差可作为惩罚或约束信号。 |
| `__init__.py` | 公共导出接口 | 提供统一的实体导入入口。 | 不直接影响策略，但能稳定环境、训练与评估代码之间的类型引用。 |

## 静态实体与动态状态

```text
静态场景参数（通常不随训练步改变）
Emitter / Pipeline / Terminal / Vessel / SubseaManifold / InjectionWell / Reservoir
                                │
                                ▼
                       仿真器的容量与物理约束
                                │
RL 动作 ────────────────────────┼──► StepResult
                                │       ├─ flows_t
                                ▼       ├─ violations
                   PhysicalState（随时间更新） └─ mass_balance_error_t
```

`PhysicalState` 中的库存、最近流量、注入历史、泊位分配、终端队列和
时变扰动覆盖值共同描述系统当前状态。若这些会影响未来的可行操作或回报，
它们应被包含在 RL 观察中，或以足够的信息进行聚合。

## RL 建模建议

### 建议的观察信息

- 各 emitter、terminal 和 reservoir 的库存及其容量占比；
- 排放源可用率、注入井可用性、注入能力与船速等扰动覆盖值；
- 管道/歧管剩余能力、注入井剩余能力和储层压力裕度；
- 船舶位置、可用时间、载货状态、泊位分配和终端卸载队列；
- 井的近期注入历史或由其计算的井底压力，尤其在启用线源模型时。

### 常见动作约束

- 捕集率必须落在 emitter 的最小利用率和可用能力范围内；
- 管道、歧管、船舶、终端泊位和注入井不能超过额定能力；
- 注入不能超出储层容量、最高压力或井底压力限制；
- 船舶在航行、装载和卸载期间不能被重复指派。

### 奖励与成本信号

可将实际封存量设为正向收益，将捕集后放空、等待时间、闲置船舶、运营成本
和约束违规设为惩罚。`Violation.magnitude_t` 适合构成连续约束成本；
`mass_balance_error_t` 应接近零，通常更适合作为仿真正确性的测试指标，而非
策略优化目标。

## 开发约定

- 静态能力或设计参数应添加到相应实体 dataclass；
- 运行时变量应添加到 `PhysicalState`，并在 `copy()` 与 `as_dict()` 中同步处理；
- 新约束应通过 `Violation` 明确记录，以便训练时诊断奖励来源；
- 修改实体字段后，应同步更新场景加载、仿真器、观察编码和单元测试。
